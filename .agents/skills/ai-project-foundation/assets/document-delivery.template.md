List every requested and applicable artifact, including each generated skill's
`SKILL.md` and required internal contract as separate rows. Reuse canonical
paths; link the current reference set from the foundation report and root/task navigation.
Unless explicitly excluded by the user, include `AGENTS.md`, `CLAUDE.md`,
`PRODUCT.md`, `CONTEXT.md`, `DESIGN.md`, and `SECURITY.md` as required rows on
every setup. If facts are unknown or a document is inapplicable to current
source, record that status, evidence checked and owner/revisit trigger; do not
omit the file. The project-skill checklist must name the five standard skills
and every selected extra; use one delivery row per SKILL.md and required local
contract/resource.
Use one row per canonical file with its actual content review, including prior
open findings, confirmed repairs and remaining defects. Generic grouped claims
do not establish that every file was reviewed.
File presence, copied headings and an empty template are not content acceptance.
Required missing content keeps setup partial until completed or concretely blocked.
